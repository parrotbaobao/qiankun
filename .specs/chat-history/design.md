# 技术设计文档:AI 对话历史

> Feature: chat-history
> 关联: requirements.md
> 技术栈: Vue3 + Composition API + Pinia + Vue Router + Axios

---

## 1. 技术选型

| 关注点 | 选型 | 理由 |
|--------|------|------|
| 组件 | Vue3 `<script setup>` | 项目既定栈 |
| 状态 | Pinia | 会话列表是跨组件共享状态,需集中管理 |
| 路由 | Vue Router | `/chat/:conversationId` 直达某会话,可分享/刷新保持 |
| 请求 | Axios 实例 | 统一拦截器、取消 token |
| 请求取消 | AbortController | 搜索竞态、切换会话时取消旧请求 |
| 长列表 | 分页 + (可选)虚拟滚动 | NFR-2 要求支撑 1000+ 会话 |

## 2. 整体架构

```
┌─────────────────────────────────────────────┐
│                  视图层 (Components)            │

│        │                 └── ConversationItem   │

└───────────────────┬─────────────────────────┘
                    │ 调用 actions / 读 state
┌───────────────────▼─────────────────────────┐
│            状态层 (Pinia: conversationStore)    │
│  state: list / current / searchKeyword / ...    │
│  actions: fetchList / search / rename / ...     │
└───────────────────┬─────────────────────────┘
                    │ 调用
┌───────────────────▼─────────────────────────┐
│          服务层 (api/conversation.ts)           │
│  纯函数式 API 封装 + AbortController             │
└───────────────────┬─────────────────────────┘
                    │ HTTP
┌───────────────────▼─────────────────────────┐
│                  后端 REST API                  │
└─────────────────────────────────────────────┘
```

设计原则:**组件只管渲染和交互,数据流全部经过 store,HTTP 细节封装在 service 层。**
这样测试时可以 mock service 层,组件和 store 都可单测。

## 3. 数据模型(TypeScript)

```typescript
// types/conversation.ts

/** 列表项:轻量,不含完整消息 */
export interface ConversationSummary {
  id: string
  title: string
  lastMessageSnippet: string   // 最后一条消息摘要,用于列表展示
  isPinned: boolean
  isTitleAutoGenerated: boolean // 区分是否被用户手动改过(AC-5.4)
  updatedAt: string             // ISO 8601
  createdAt: string
}

/** 单条消息 */
export interface Message {
  id: string
  conversationId: string
  role: 'user' | 'assistant'
  content: string
  createdAt: string
}

/** 会话详情:列表项 + 完整消息 */
export interface ConversationDetail extends ConversationSummary {
  messages: Message[]
}

/** 分页响应包装 */
export interface Paginated<T> {
  items: T[]
  page: number
  pageSize: number
  total: number
  hasMore: boolean
}
```

## 4. API 契约(与后端约定)

> 约定:列表/搜索为读,重命名/删除/置顶/追加消息为写。所有写操作要保证幂等或可回滚。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/conversations?page=&size=&sort=updatedAt:desc` | 分页拉列表(AC-1.1/1.2) |
| GET | `/api/conversations/search?q=&page=&size=` | 搜索标题+内容(AC-2.2) |
| GET | `/api/conversations/:id` | 拉单会话完整消息(AC-1.4/4.1) |
| PATCH | `/api/conversations/:id` | 改 title 或 isPinned(AC-3.1/3.5) |
| DELETE | `/api/conversations/:id` | 删除会话(AC-3.3) |
| POST | `/api/conversations/:id/messages` | 追加消息(AC-4.2) |
| POST | `/api/conversations/:id/generate-title` | 触发标题生成(AC-5.1) |

PATCH 请求体示例:
```jsonc
// 重命名
{ "title": "qiankun 沙箱隔离讨论" }
// 置顶
{ "isPinned": true }
```

排序契约(AC-3.5):后端按 `isPinned DESC, updatedAt DESC` 返回。
前端做乐观更新时也要复刻同样的排序逻辑,保证一致。

## 5. 状态管理设计(Pinia store)

```typescript
// stores/conversation.ts (结构示意,非完整实现)
export const useConversationStore = defineStore('conversation', () => {
  // ---- state ----
  const list = ref<ConversationSummary[]>([])   // 当前展示的列表(列表或搜索结果)
  const current = ref<ConversationDetail | null>(null)
  const searchKeyword = ref('')
  const page = ref(1)
  const hasMore = ref(true)
  const loading = ref(false)
  const error = ref<string | null>(null)

  // ---- getters ----
  // 列表已由后端排序;前端乐观更新后用此 getter 保持有序
  const sortedList = computed(() =>
    [...list.value].sort((a, b) => {
      if (a.isPinned !== b.isPinned) return a.isPinned ? -1 : 1
      return +new Date(b.updatedAt) - +new Date(a.updatedAt)
    })
  )

  // ---- actions ----
  // fetchList / loadMore / search / openConversation /
  // rename / remove / togglePin / appendMessage / generateTitle
  // (具体在 tasks 中逐个实现)

  return { list, current, searchKeyword, page, hasMore, loading, error,
           sortedList, /* ...actions */ }
})
```

关键点:`list` 这一个数组同时承载「完整列表」和「搜索结果」两种视图,
由 `searchKeyword` 是否为空来区分语义,避免维护两份状态导致不同步。

## 7. 关键技术方案

### 7.1 搜索防抖 + 竞态取消(AC-2.1 / 2.5)

```typescript
// 防抖:停止输入 300ms 才触发
// 竞态:每次新搜索前 abort 上一个请求,只认最后一次结果
let controller: AbortController | null = null

async function search(keyword: string) {
  controller?.abort()              // 取消上一次
  controller = new AbortController()
  try {
    const res = await api.searchConversations(keyword, { signal: controller.signal })
    list.value = res.items
  } catch (e) {
    if (e.name !== 'AbortError') error.value = '搜索失败,请重试'
    // AbortError 是主动取消,静默忽略
  }
}
```
> 防抖建议用 VueUse 的 `useDebounceFn`,或自己写一个 setTimeout 版本。

### 7.2 乐观更新 + 回滚(AC-3.6 / 3.7)

以「置顶」为例:

```typescript
async function togglePin(id: string) {
  const item = list.value.find(c => c.id === id)
  if (!item) return
  const prev = item.isPinned          // 1. 记录旧值
  item.isPinned = !item.isPinned      // 2. 先改 UI(乐观)
  try {
    await api.patchConversation(id, { isPinned: item.isPinned })
  } catch {
    item.isPinned = prev              // 3. 失败回滚
    error.value = '操作失败,已撤销'
  }
}
```

### 7.3 自动生成标题的时机与降级(AC-5.1 ~ 5.4)

```
新会话首轮问答完成
   │
   ├─ isTitleAutoGenerated 仍为 true 且用户没手动改过?
   │        │ 是
   │        ▼
   │   POST /generate-title (异步,不阻塞输入框)
   │        │
   │        ├─ 成功 → 更新 title,标记 isTitleAutoGenerated=true
   │        └─ 失败 → 回退「新对话」/ 首句前 12 字,用户照常使用
   │
   └─ 用户已手动重命名 → 跳过(AC-5.4)
```

方案选择(对应 Open Question Q2):**推荐后端生成**。
后端在 `/generate-title` 内部调用模型总结首轮内容,前端只负责触发和接收结果。
好处:不暴露模型调用细节给前端、token 计费集中、前端逻辑简单。

### 7.4 切换会话时取消未完成的加载

打开会话 B 时,若会话 A 的消息还在加载,应 abort A 的请求,防止 A 的响应
晚到覆盖掉 B 的内容(典型竞态)。复用 7.1 的 AbortController 模式。

### 7.5 长列表性能(NFR-2)

- 默认分页加载即可满足大多数场景。
- 当单页 DOM 节点过多导致卡顿时,再引入虚拟滚动(如 `vue-virtual-scroller`)。
- 不要一开始就上虚拟滚动——先用分页,有实测卡顿数据再优化(避免过早优化)。

## 8. 错误与边界处理

| 场景 | 处理 |
|------|------|
| 列表加载失败 | 展示重试按钮,不清空已加载数据(AC-1.6 精神) |
| 删除当前会话 | 清空 `current`,路由回历史空态(AC-3.4) |
| 搜索请求被取消 | 静默忽略 AbortError,不报错 |
| 标题生成失败 | 降级,绝不阻塞对话(AC-5.3) |
| 重命名空标题 | 前端校验拦截,不发请求(AC-3.2) |

## 9. 测试策略

- **service 层**:mock HTTP,验证参数拼装、AbortController 传递。
- **store**:mock service,验证乐观更新与回滚、排序、搜索/列表状态切换。
- **组件**:Vue Test Utils,验证防抖触发、二次确认弹窗、空/加载态渲染。
- 重点覆盖竞态(AC-2.5)和回滚(AC-3.7)这两个最容易出 bug 的点。
