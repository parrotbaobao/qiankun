# 实施任务:AI 对话历史

> Feature: chat-history
> 关联: requirements.md / design.md
> 约定:每个任务尽量原子化、可独立验证;勾选前需通过对应测试。

## 阶段 0:类型与基础设施

- [ ] **T0** 定义类型
  - 创建 `types/conversation.ts`,落地 `ConversationSummary` / `Message` /
    `ConversationDetail` / `Paginated<T>`(见 design.md §3)
  - 验收:类型可被 store 与 service 正确引用,`tsc` 无报错

- [ ] **T1** 封装 API service 层
  - 创建 `api/conversation.ts`,实现 design.md §4 全部 7 个接口
  - 每个读接口支持传入 `AbortSignal`
  - 统一用项目既有 Axios 实例(含鉴权拦截器)
  - 验收:`conversation.service.spec.ts` —— mock HTTP,断言 URL/方法/参数/signal 透传

## 阶段 1:列表与查看(US-1)

- [ ] **T2** store 基础 state + `fetchList` / `loadMore`
  - 实现分页拉取、`hasMore` 计算、`loading` / `error` 维护
  - 验收:`conversation.store.spec.ts` 覆盖首屏加载、加载更多、加载失败置 error

- [ ] **T3** `sortedList` getter
  - 实现 `isPinned DESC, updatedAt DESC` 排序(design.md §5)
  - 验收:单测验证置顶项恒在前、组内按时间倒序

- [ ] **T4** `ConversationItem.vue`
  - 展示标题 / 摘要 / 相对时间 / 置顶标记(AC-1.3)
  - 相对时间用 `dayjs` 或 `Intl.RelativeTimeFormat`
  - 验收:组件测试,传入不同 props 渲染正确,置顶项有标记

- [ ] **T5** `ConversationList.vue`
  - 渲染 `sortedList`、滚动到底触发 `loadMore`、骨架屏、空状态(AC-1.5/1.6)
  - 验收:空数组显示空态;加载中显示 skeleton;触底回调被调用

- [ ] **T6** `openConversation` action + 详情还原(AC-1.4)
  - 点击项 → 拉 `/:id` → 写入 `current`,切换会话时 abort 旧请求(design.md §7.4)
  - 路由更新为 `/chat/:id`,刷新可保持
  - 验收:store 测试覆盖正常加载 + 切换时旧请求被取消

## 阶段 2:搜索(US-2)

- [ ] **T7** `search` action + 防抖 + 竞态取消

  - 空关键词恢复完整列表(AC-2.3)
  - 验收:store 测试覆盖正常搜索、连续输入只认最后一次、清空恢复列表

- [ ] **T8** `ChatHistorySearch.vue` + 无结果态
  - 搜索框、清空按钮、无结果提示(AC-2.4)
  - (可选)命中关键词轻量高亮
  - 验收:组件测试,输入触发 emit、清空恢复、无结果文案渲染

## 阶段 3:管理操作(US-3)

- [ ] **T9** `rename` action(乐观更新 + 回滚 + 空标题校验)

  - 验收:成功更新、空标题被拦截、请求失败回滚

- [ ] **T10** `togglePin` action(乐观更新 + 回滚 + 重排序)

  - 验收:乐观更新、失败回滚、置顶后位置变化

- [ ] **T11** `remove` action + 删除当前会话处理
  - 二次确认在组件层;删除当前会话则清空 `current` 回空态(AC-3.3/3.4)
  - 验收:删除后列表移除该项;删的是 current 时 current 被清空

- [ ] **T12** `ItemMenu.vue`
  - 重命名(内联输入)、删除(二次确认弹窗)、置顶/取消置顶
  - 验收:组件测试,确认弹窗出现、确认后才回调、内联输入回填原标题

## 阶段 4:继续对话与自动标题(US-4 / US-5)

- [ ] **T13** `appendMessage` action(AC-4.2/4.3)
  - 新消息追加到 `current.messages` + 调 `POST /:id/messages`
  - 更新该会话 `updatedAt` 使其在列表上移
  - 验收:消息追加成功;列表中该会话位置上移

- [ ] **T14** `ChatWindow.vue` 集成继续对话(AC-4.1)
  - 渲染 `current.messages`,输入框发送走 `appendMessage`
  - 验收:打开历史还原全部消息;发送后消息出现在底部

- [ ] **T15** `generateTitle` action + 触发时机 + 降级(AC-5.1~5.4)
  - 新会话首轮问答完成后触发(design.md §7.3)
  - 已手动改过标题则跳过;失败降级不阻塞
  - 验收:首轮后触发一次、手动改过的不触发、失败时回退默认标题

## 阶段 5:打磨

## 执行建议

1. 严格按阶段推进,每完成一个阶段就能跑通一条完整用户路径,便于阶段性 demo。
2. 每个任务先写测试(对应 AC)再写实现,符合 SDD「spec → 测试 → 代码」的链路。
3. 任何需求变化,先回去改 requirements/design,再回到这里调整任务,不要直接改代码。
